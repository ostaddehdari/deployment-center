## بازیابی قطعی API و تأیید هم‌زمان تغییرات نمایه‌ساز

- جایگزینی موفقیت کاذب `nest build` با کامپایل صریح TypeScript که پوشهٔ `dist` را از صفر تولید می‌کند.
- ایجاد پیکربندی build استاندارد برای پروژه‌ای که فاقد `tsconfig.build.json` بوده است.
- الزام وجود و صحت نحوی `apps/api/dist/main.js` پس از هر build.
- بررسی پاسخ JSON مسیر OTP هم مستقیماً روی پورت API و هم از مسیر عمومی Nginx؛ پاسخ ۵۰۲ یا HTML پذیرفته نمی‌شود.
- تأیید ثبات PID سرویس API، صفحهٔ نمایه‌ساز و assetهای Nuxt پیش از ثبت موفقیت.
- اجرای تست‌های کامل قرارداد و تست‌های اختصاصی toolbox/درخت نمایه‌ها.
- ممیزی دیتابیس برای والد بودن «موضوع» نسبت به «زیرموضوع» و «کلید پردازش» در هر سه فرم، حداکثر سه سطح زیرشاخه و مرجعیت کامل خود نمایه‌ساز.
- بدون تغییر در داده‌های دیتابیس یا build وب؛ همراه با پشتیبان‌گیری و بازگردانی فایل‌های build در صورت شکست.
